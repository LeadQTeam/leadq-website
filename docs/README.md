# Site docs

## How the pages are built

Every `.html` file in the repo root is generated by [`build-site.js`](build-site.js).
The site itself is plain static HTML with no build step: GitHub Pages serves the
generated files as they are. The script exists so the parts that repeat on every
page (the nav, the footer, the phone mockups, the plan cards, the channel icons)
are written once instead of twelve times.

```bash
node docs/build-site.js
```

It writes into the repo root and prints each file it wrote. Re-run it after editing
the script, then commit the regenerated HTML alongside it.

**Edit the script, not the generated HTML.** A hand edit to `index.html` survives
until the next run and is then overwritten.

`styles.css` and `site.js` are hand-written and are *not* generated. Edit those directly.

## Where the legal text comes from

`privacy-policy.html` and `terms-of-service.html` take their wording verbatim from
commit `7210f5b`, the last one before the redesign. The commit is pinned in the
script as `LEGAL_SRC`. That is deliberate: reading the text from `HEAD` worked only
until the redesign shipped, after which it parsed its own output.

## The other files here

- `LEADQ-REDESIGN-BUILD-SPEC.md` — the spec the redesign was built to
- `DESIGNER-HANDOFF.md`, `REDESIGN-BRIEF.md` — the brief behind it
- `leadq-redesign-brochure.html` — the visual proposal

`_config.yml` keeps this whole folder out of the published site, so none of it is
served from leadq.co. The repo is public, so anything here is readable on GitHub.
